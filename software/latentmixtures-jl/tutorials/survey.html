Complex survey data

Most population surveys are not simple random samples. Respondents are drawn in clusters (primary sampling units, PSUs: schools, villages, census tracts) within strata (regions, urban/rural), with unequal selection probabilities that the sampling weights undo. Cases in the same PSU resemble each other, so they carry less information than the same number of independent cases. Model-based (MLR) standard errors can then misstate the uncertainty (typically understate it), and tests built on the log-likelihood can be too liberal.

lca, lpa, growth, lta and multigroup models (group) take the design as cluster and strata, one value per row of the data, alongside weights. This is Mplus TYPE = MIXTURE COMPLEX with CLUSTER, STRATIFICATION and WEIGHT:

hereMplus
lca(Y, K; weights = w, cluster = psu, strata = stratum)WEIGHT = w; CLUSTER = psu; STRATIFICATION = stratum; with TYPE = MIXTURE COMPLEX

What changes, and what does not

  • Estimates and the log-likelihood do not change: they are the weighted (pseudo-)maximum-likelihood estimates, whatever the design. So do BIC, entropy and the classification tables.

  • Standard errors (parameters, vcov, one-step regressions, r3step, bch, dcat) use the design-based sandwich I⁻¹ B I⁻¹ with the meat (Asparouhov 2005)

    B = Σ_h n_h/(n_h − 1) Σ_c (z_hc − z̄_h)(z_hc − z̄_h)ᵀ,

    where z_hc is the sum of the weighted case scores in PSU c of stratum h, n_h the number of PSUs of stratum h and z̄_h their mean. Without strata there is a single stratum; without cluster every row is its own PSU (strata only).

  • The MLR scaling correction factor (scaling_factor) is computed from the same meat, so compare_models gives the design-based Satorra–Bentler scaled difference test. The unscaled likelihood-ratio test (chisq, lrtest) ignores the design: under clustering only the scaled version is valid.

  • lmr uses the design-based score cross-products; blrt is not available (Mplus does not allow TECH14 with TYPE = MIXTURE COMPLEX).

Example

The validation data (validation/make_complex_data.jl) have 150 PSUs of 8 respondents in 10 strata, sampling weights, and a PSU-level effect on class membership.

using LatentMixtures, DelimitedFiles
A = readdlm(joinpath(pkgdir(LatentMixtures), "validation", "data", "complex.dat"))
A = [x == -999 ? missing : x for x in A]
Y = A[:, 1:8]                                    # eight binary indicators
psu, stratum, w = A[:, 33], A[:, 34], A[:, 35]
m  = lca(Y, 3; weights = w)                                  # weights only (MLR)
mc = lca(Y, 3; weights = w, cluster = psu, strata = stratum) # complex design
loglikelihood(m) == loglikelihood(mc)            # identical estimates
true
pt, pc = parameters(m), parameters(mc)
ratio = pc.se ./ pt.se                            # design-based / MLR standard errors
i = pt.kind .== "class logit"
(class_logits = round.(ratio[i]; digits = 2), all_parameters = round.(extrema(ratio[pt.se .> 0]); digits = 2))
(class_logits = [1.11, 0.99], all_parameters = (0.87, 1.11))

Here the design changes the standard errors in both directions: the logit of the class whose size depends on the PSU effect gets an SE about 11% larger, while several item parameters get somewhat smaller SEs. A design effect is not always an inflation: it depends on how the case scores of a parameter covary within PSUs and on what the strata absorb, so it is data- and parameter-specific, which is why the design should be declared rather than guessed. The scaling factor changes too:

(mlr = scaling_factor(m), complex = scaling_factor(mc))
(mlr = 1.2887145141499445, complex = 1.281646322423807)

Mplus equivalence

Checked against Mplus 8.3 TYPE = MIXTURE COMPLEX (see Validation): log-likelihood, scaling factor and every standard error to the printed precision for LCA (with a boundary threshold), LPA, one-step covariates, GMM, R3STEP, BCH and multigroup LCA; log-likelihood and scaling factor for LTA. The following details follow Mplus:

  • PSUs are nested in strata: equal cluster codes in different strata are different PSUs (Mplus warns and does the same).
  • A stratum with a single PSU is kept and contributes z zᵀ (uncentred, factor 1); dropping it would change the SEs. Mplus prints no warning for such strata.
  • The factor n_h/(n_h − 1) applies within every stratum, including strata-only designs (each row a PSU), but not without a design (plain MLR, Σ wᵢ² sᵢ sᵢᵀ).
  • Weights are rescaled to sum to the number of analysed rows; rows with every indicator missing (and, with covariates, rows with a missing covariate) are dropped from the design. Analysed rows may not have a missing cluster or strata.

Caveats

  • The design affects uncertainty only. Weights change the estimates; clusters and strata do not. A model of the between-PSU variation itself is a multilevel mixture (Mplus TYPE = TWOLEVEL MIXTURE), which is not implemented.
  • Design-based SEs need enough PSUs: with few PSUs per stratum the meat is imprecise. The usual guidance is at least 30–50 PSUs overall.
  • Tests based on the log-likelihood need the scaled versions: use compare_models (chisq_scaled, p_scaled), not 2ΔLL.
  • LTA and multigroup models take cluster and strata but not weights. Multigroup models report design-based standard errors (parameters); for LTA the design enters the scaling factor and compare_models (standard errors to follow).
  • Not implemented: the finite population correction (Mplus FINITE), replicate weights (REPWEIGHTS) and subpopulation analysis (SUBPOPULATION). DCAT with a design has no Mplus counterpart (Mplus refuses DCAT with COMPLEX).
