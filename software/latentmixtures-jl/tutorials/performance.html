GPU and performance

Threads

Random starts (stage 1 and stage 2), bootstrap replications (blrt) and the row blocks of the standard-error computations run in parallel on Julia threads. Start Julia with threads:

julia -t auto            # or: julia -t 8, or JULIA_NUM_THREADS=8

Every start uses its own random-number stream, derived from (seed, start number), so the solution does not depend on the number of threads (up to floating-point rounding). While starts run in parallel, BLAS is set to one thread and restored afterwards.

Large samples

  • LCA: identical response patterns are collapsed and weighted, so an EM iteration costs time in the number of distinct patterns, not in n. (Covariate models keep one row per case.)
  • CPU kernels: every start runs fused, single-threaded E- and M-step loops with one K × n buffer and no n-sized allocations per iteration.
  • Standard errors (parameters, scaling_factor) use forward-mode automatic differentiation over blocks of rows; their cost grows with n·d² for d parameters. They are computed on first use and cached.
  • Convergence: the default tol = 1e-10 (change in log-likelihood per case) is tight, which costs iterations in flat likelihoods; a looser tol speeds up exploratory runs (check the final model with the default). stage1_iter and starts set the cost of the random-start search.

GPU

With CUDA.jl loaded, device = :cuda runs every E- and M-step of lca and lpa as dense matrix products on an NVIDIA GPU (package extension LatentMixturesCUDAExt; CUDA is a weak dependency and is not installed with the package):

using CUDA, LatentMixtures
# Four wellbeing profiles (sleep, activity, diet, stress, loneliness, life satisfaction) on the GPU
w = dataset("wellbeing")
X = w[:, [:sleep, :activity, :fruitveg, :stress, :lonely, :lifesat]]
CUDA.functional()                       # must be true
p = lpa(X, 4; variances = :varying, device = :cuda)
classprobs(p)                           # the same solution as on the CPU (up to rounding)

On the GPU the random starts run one after another (each start is already parallel on the device), arrays are Float64, and only the estimation runs on the device; the post-estimation functions use the host copy of the data kept with the model. The GPU formulation can be exercised on the CPU with device = :array (used in the tests).

Benchmarks

The tables below are from the README; scripts and logs are in validation/bench/ and validation/logs/.

Against Mplus, same machine

Mplus 8 and LatentMixtures on one Apple M-series laptop, the same models, STARTS = 500 100, STITERATIONS = 20, standard errors included, Mplus PROCESSORS = 1 / 8 and Julia -t 1 / -t 8. LatentMixtures times are for a fresh Julia process (start-up, loading and any compilation included); every log-likelihood agrees with Mplus to 3 decimals. The machine was shared with other jobs (load 4–20), so the numbers are indicative. LatentMixtures converges more tightly (tol = 1e-10 per case), which costs iterations.

(ranges: runs on different nodes.)

GPU (validation/gpu_bench.jl, one H100 vs 16 CPU threads): LPA with n = 1,000,000, J = 10, K = 6, profile-specific variances, starts (32, 8), maxiter = 300: 47–71 s on CPU (two runs), 3.6–3.7 s on GPU, same log-likelihood. One EM iteration takes 239 ms on one CPU core and 1.2–1.5 ms on the GPU.

Covariate models need a Newton step for the multinomial logit in every M-step; on one core, LPA n = 100,000, K = 4, 3 covariates took about 6× as long as the same model without covariates, including the standard errors.
