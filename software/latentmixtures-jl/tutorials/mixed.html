Mixed and count indicators

mixture fits one latent class model to indicators of several types:

keywordindicator typewithin-class distributionMplus
categoricalbinary or polytomousmultinomial (item-response probabilities)CATEGORICAL = u
continuouscontinuousnormal (mean, variance)(default)
countcountPoisson (log rate)COUNT = u (p)
negbincountnegative binomial NB2 (log mean, dispersion α, Var = μ + αμ²)COUNT = u (nb)
zipcountzero-inflated Poisson (log rate, inflation probability π)COUNT = u (pi)

All indicators are independent within class (local independence), so the class-specific likelihood is the product of the indicators' densities over the observed ones (missing values by full-information ML). As in Mplus, the variances of continuous indicators, the negative binomial dispersions and the zero-inflation probabilities are equal across classes unless variances, dispersion or inflation is :varying.

Adverse childhood experiences and depressive symptoms

The aces data have eight binary adversity items and a depressive-symptom score (depress, a count of 0–24 that depends on the class). Counts like this are usually overdispersed relative to the Poisson, so we compare the two count models:

using LatentMixtures
d = dataset("aces")
mp = mixture(d, 4; categorical = r"^ace_", count = :depress, starts = (400, 80))    # Poisson
mn = mixture(d, 4; categorical = r"^ace_", negbin = :depress, starts = (400, 80))   # negative binomial

All three types

Notes

  • Indicators are reported in m.names by type (categorical, continuous, Poisson, negative binomial, zero-inflated) and, within type, in the order given.
  • A zero-inflated Poisson adds one parameter per item (or per item and class) over the Poisson; it is identified only if the counts have more zeros than a Poisson allows. The negative binomial reduces to the Poisson as α → 0; a dispersion that goes to 0 is held fixed at the boundary in the standard errors.
  • The estimates, standard errors, MLR scaling factors and three-step results agree with Mplus 8 on the validation cases (see the Validation page).
