Mplus interoperability and start values

Random starts (defaults)

Every model is estimated by EM from Mplus-style two-stage random starts: starts = (100, 20) and stage1_iter = 20 draw 100 random starts, run 20 EM iterations from each (stage 1), and run the 20 with the highest log-likelihood to convergence (stage 2), i.e. Mplus STARTS = 100 20; STITERATIONS = 20 (the Mplus defaults are STARTS = 20 4; STITERATIONS = 10). Start s draws its values from its own random-number stream, fixed by (seed, s), so the solution does not depend on the number of threads. The stage-2 starts are listed, best first, in m.finals (id, ll, iterations, converged); convergence checks that the best log-likelihood is replicated.

Two further ways to start EM, as in Mplus:

JuliaMpluswhat it does
lca(Y, K; start = m) or start = svalues(m)user starting values, STARTS = 0 (OUTPUT: SVALUES prints them)EM from the given estimates only, no random starts
lca(Y, K; optseed = id), refit_start(m, id)OPTSEED = seedrerun random start id (stage 1 and stage 2) exactly as it ran in the multistart

start and optseed are keywords of lca, lpa, growth and lta (single- and multigroup). svalues returns the estimates of a fit in reported class order and on the original scale, as a NamedTuple that can be edited (e.g. to start from a theory-driven profile) and passed as start:

using LatentMixtures
d = dataset("aces"); Y = d[:, r"^ace_"]
m  = lca(Y, 4)
m.finals                                   # stage-2 starts, best first
loc = refit_start(m, m.finals[end].id)     # the worst stage-2 start: a local maximum?
mw  = lca(Y, 4; weights = d.weight, start = m)   # weighted fit started at the unweighted one

to_mplus writes the analysed data (free format, missing values flagged with -999 or another value absent from the data, categorical indicators coded 0, …, C − 1) and an Mplus input that specifies the same model:

With svalues = true (default) every free parameter gets the Julia estimate as its starting value (*value) and the input uses STARTS = 0 and tight EM criteria, so Mplus converges to the same solution with the classes in the same order. With run = true (and Mplus installed) the input is run as well, and compare_mplus puts the two fits side by side:

r = to_mplus(m; file = "aces4.inp", run = true)
c = compare_mplus(m, r.out)     # LL, npar, BIC; every estimate and SE, max differences
c.table                         # section, header, param, julia, mplus, diff, julia_se, mplus_se, …

read_mplus parses any Mplus mixture output (fit statistics and MODEL RESULTS, in the layout of MplusAutomation's readModels()$parameters$unstandardized).

Round trips for the validation models

validation/mplus_roundtrip.jl fits every exportable model type of validation/mplus in Julia (starts = (100, 20)), exports it with start values, runs Mplus 8.3 and compares (validation/roundtrip/RESULTS.txt), 61 models in all. Mplus prints three decimals, so differences up to 5e-4 are rounding. maxΔ/SE is the largest difference in units of the Mplus standard error; nbd counts weakly identified parameters (at ±15 or with Mplus SE > 5) excluded from the maxima. Julia standard errors are those of parameters (robust, or design-based with cluster/strata). Runs of the original validation/mplus inputs from Mplus's own random starts (classes in another order) are compared in the test suite as well: compare_mplus finds the class order and re-references the class logits.

Notes:

  • lca_bin_k3, mg_full, mg_none: the largest differences are in weakly identified thresholds (Mplus SE 3.2 in lca_bin_k3), far below one standard error; see "Known differences" on the Validation page.
  • cx_lta: the 2.7e-3 (SE 1.1e-2) difference is a weakly identified threshold (0.005 SE).
  • GMM, quadratic: the Julia fit did not converge within maxiter = 5000 (the growth factor covariance matrix is nearly singular; convergence(m) reports it). Started from the Julia estimates, Mplus's quasi-Newton steps reach a log-likelihood 0.083 higher. This is the case convergence warns about; use more iterations or a lower degree.
  • Not exported: R3STEP, BCH, DCAT (aux3*, dcat) and the LMR/BLRT runs (*_lrt) are post-estimation computations on an exported measurement model, not models of their own.
  • Multigroup models with covariates or weights, and categorical LTA items whose category set differs between waves under full invariance, are not exported (the second throws an error because Mplus would number the categories differently).
