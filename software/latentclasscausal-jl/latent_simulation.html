Latent classes and interventions: simulation

validation/sim_latent.jl, run as Slurm job arrays on the Nibi cluster (Alliance Canada; Julia 1.12.5, 8 threads per task; 576 tasks of 250 replicates plus 222 top-up tasks). Every setting is crossed with n ∈ {500, 2000, 5000}, K ∈ {2, 3, 4} classes and strong or weak class separation (item logits multiplied by 1 or 0.6; e.g. P(item | low class) ≈ 0.12 vs 0.23), giving 18 cells per setting and 1,000 replicates per cell (EM with 30 + 6 starts per fit). Truth is computed from the data-generating process by Monte Carlo with 10⁶ draws (quadrature over U in part Bu). Classes are aligned to the true ones by their item profiles. Coverage is of nominal 95% Wald intervals.

Designs. Item logits for class 1 (low adversity), 2 (high), 3 (items 1–4 high), 4 (items 5–8 high), the first K classes used.

  • a0, a1, b — exposure classes: X = (x₁ ~ N(0, 1), x₂ ~ Bernoulli(0.4)) → C (multinomial logit) → 8 binary exposures (class-specific probabilities only); S = {1, 2}, set both to 0 vs the natural course. Y = a₁ + 0.8a₂ + 0.6a₁a₂ + βa₄ + 0.5x₁ + 0.3x₂ + 0.5a₁x₁ + γ·1(C = 2) + ε. a0: β = γ = 0; a1: β = 0.5; b: β = 0.5 and a direct effect γ = 1.5 of the high-adversity class. outcome = :quadratic. Class adjustment uses a K-class LCA of a₃–a₈ with covariates. Bootstrap rows: 100 refits of the class model for every fifth replicate of a0.
  • A — latent class outcome: 4 exposures from a logistic chain on X (so the propensity model is correct), outcome classes by a multinomial logit on the exposures and X, 8 indicators; intervene_latent_outcome for set-to-0 and shift(0.5), linear working models.
  • Bu, Bs, Bd0, Bd1 — intervene_membership designs (binary treatment, 2 confounders, 8 class indicators): Bu with an unmeasured U ~ N(0, 1) of treatment and class 1 (logit 0.8 in both), intervene_membership_sensitivity at the true bias; Bs intervene_subgroup for x₁ > 0; Bd0/Bd1 intervene_dif without / with DIF (items 1–2 shifted by 1 logit among the treated).

Warm-start bootstrap

The bootstrap rows of this page (share_delta_boot, class_effect_boot) refit the class model from random starts, boot_starts = (30, 6), which is the default. The alternative boot_starts = :warm starts every refit at the full-sample estimates: about five times faster and with fewer label switches between replicates.

Same data, both start rules (validation/warm_vs_random.jl, ace_study, n = 2500, K = 3, B = 200, 8 threads on a Nibi node; bootstrap seeds 1–3):

With weakly separated classes the warm start understates the bootstrap variability: replicates started at the full-sample solution stay near it, so the uncertainty from other local maxima and from class labelling is missed. Random starts are therefore the default; use :warm only for quick exploration when classes are well separated.
